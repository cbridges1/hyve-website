## Run it where you need it

The same objects and the same commands everywhere.

<CardGroup cols={3}>
  <Card title="On your laptop" icon="terminal" href="/docs/running/local-mode" color="#3b82f6">
    `hyve local up` runs hyve on a K3s container in Docker and signs you in. CAPD clusters run as containers next to it.
  </Card>

  <Card title="In CI" icon="code-branch" href="/docs/guides/ci" color="#22c55e">
    Local mode in a pipeline: create a cluster from a template for a test run, delete it after. State can be cached between jobs.
  </Card>

  <Card title="On a server" icon="server" href="/docs/running/standalone" color="#8b5cf6">
    `hyve install` puts hyve on any cluster, with whatever's missing of Cluster API, cert-manager and Fleet. Users sign in with a password or your identity provider.
  </Card>
</CardGroup>

## What you get

<CardGroup cols={2}>
  <Card title="Templates with locks and expiry" icon="layer-group" href="/docs/concepts/templates">
    Defaults for a ClusterClass's variables, the ones users can't change, and a cron schedule that deletes clusters when it's due.
  </Card>

  <Card title="Apps on every cluster" icon="cubes" href="/docs/concepts/resources">
    A template's resources are Fleet HelmOps, Bundles and GitRepos. Every cluster made from it gets them, and Fleet keeps them there.
  </Card>

  <Card title="One sign-in for every cluster" icon="key" href="/docs/concepts/access">
    kubectl, Helm and k9s reach each cluster through hyve as you, with your own permissions. No admin kubeconfigs handed out.
  </Card>

  <Card title="Clusters that can't reach you" icon="arrow-right-arrow-left" href="/docs/concepts/delivery">
    A cluster whose agent can't connect gets its resources pushed from the management side instead, with nothing to configure.
  </Card>

  <Card title="A web UI" icon="window" href="/docs/guides/web-ui">
    Clusters, templates and environments, an explorer for any cluster's objects, and a kubectl shell in the browser.
  </Card>

  <Card title="A way off Rancher" icon="right-left" href="/docs/running/replacing-rancher">
    `hyve install --replace-rancher` removes Rancher, keeps Fleet and Cluster API running, and takes over their providers.
  </Card>
</CardGroup>
