## Clusters as code

A cluster is one YAML file. Create it and the cluster is created, edit it and it's updated, mark it `delete: true` and it's deleted. Locally it's a file; in Kubernetes it's a custom resource — the same shape either way.

```yaml
apiVersion: hyve.io/v1alpha1
kind: ClusterDefinition
metadata:
  name: web
spec:
  driver:
    source: github.com/cbridges1/hyve-capi-module
    version: v0.2.0
  mgmtCluster: capi-mgmt
  params:
    cluster_class: aws-small
    kubernetes_version: v1.34.8
    worker_count: "3"
```

Templates stamp out clusters to a pattern, lifecycle hooks run workflows before and after each change, and `hyve cluster auth` hands you a working kubeconfig.

## Bring your own provisioner

A [module](/docs/concepts/modules) is a small, versioned set of scripts — create, status, scale, auth, delete — so anything you can script can provision a cluster: Terraform, Crossplane, Cluster API, or a provider's CLI. Hyve embeds no cloud SDKs; credentials stay where your tools already keep them.
