An **environment** (`hyve env`) is a named pointer to either a local directory of cluster/template/workflow YAML, or a cluster-mode API URL — nothing more. Hyve has no built-in git functionality: it never clones, pulls, pushes, or commits anything on its own. `hyve env` just tracks *where* your commands read from and write to.

<Warning>
  This replaces an earlier `hyve git`/`hyve set-state` split (both removed) — `hyve env` is the one command group for registering and switching between directories or cluster targets.
</Warning>

## What an environment is

```bash
hyve env create prod --path ~/repos/prod-config
hyve env use prod              # subsequent commands read/write here
hyve env current                # show the active environment
hyve env list                   # show every registered environment
hyve env remove staging         # deregister (never deletes the directory itself)
hyve env path [name]            # print an environment's local path
```

An environment is a thin record — a name, a local path, and (optionally) a cluster API URL — stored locally in `~/.hyve/hyve.db`. Hyve never manages a clone of anything; `--path` just points at a directory you already have.

## Local mode: a plain directory, git optional

```bash
hyve env create my-project --path ~/repos/my-project
```

That directory holds `clusters/`, `templates/`, `workflows/`, `hyve.yaml`, and `hyve.lock` — plain files `hyve reconcile` reads and writes directly. Whether that directory happens to be a git working tree is entirely up to you:

<Tip>
  Want git? `git init`/`git clone` the directory yourself, `git add`/`git commit`/`git push` as you always would. Hyve never touches git at all — see [Version Control](/docs/concepts/gitops) for the full pattern (typically `git pull && hyve reconcile && git commit -am "..." && git push`, run locally or from CI).
</Tip>

Don't want git? Skip it entirely — `hyve env create --path` works against any plain directory, tracked or not.

## Cluster mode: an API URL, no local directory required

```bash
hyve env create prod-cluster --api-url https://hyve-api.example.com
hyve env use prod-cluster
hyve login              # --api-url defaults to the active environment's
```

<Note>
  **Environments and `hyve login` are two independent concepts.** `hyve env` only ever picks which directory `hyve reconcile` reads from, or which API URL is "active" for `hyve login` to default to. `hyve login` is one global, machine-wide credential — like `gh auth login` — not scoped to whichever environment is active. Switching environments never logs you out; logging in/out never changes the active environment.
</Note>

`hyve login --api-url <url>` also auto-registers the environment for you if that URL isn't already known — so a single `hyve login --api-url https://hyve-api.example.com` is often all you need; an explicit `hyve env create --api-url` is only for pre-registering a target before you're ready to log in.
