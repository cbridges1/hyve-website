Grants a hyve user or group a role on clusters, as Rancher's cluster role
bindings do: owner (everything), member (see the cluster, create namespaces)
or read-only (read everything but Secrets). Without --cluster it covers every
cluster in the environment, now and later. A cluster's creator is its owner
automatically.

--role environment-member lets them create and manage clusters in the environment.

```text
  hyve access [command]
```

**Flags**

```text
  -e, --env string                  environment (namespace) of the clusters (default: the context's; see 'hyve env use')
  -h, --help                        help for access
      --kubeconfig string           talk to a management cluster with this kubeconfig instead of a signed-in server (admins, CI)
      --server string               saved server to use (default: the current one; see 'hyve context list')
      --template-namespace string   namespace of templates and their Deployments (default: the context's, or capi-clusters)
```

### hyve access grant

```text
  hyve access grant [USER] --role owner|member|read-only|environment-member|deployer [--cluster NAME] [--group GROUP] [flags]
```

**Examples**

```text
  hyve access grant alice --role owner --cluster web
  hyve access grant --group ops --role read-only          # every cluster in the environment
  hyve access grant bob --role environment-member -e ci
  hyve access grant ci --role deployer
```

**Flags**

```text
      --cluster string   one cluster (default: every cluster in the environment)
      --group string     a hyve group instead of a user
  -h, --help             help for grant
      --role string      owner, member, read-only, environment-member or deployer
```
