<Warning>
  `hyve git` has been removed. Hyve never had built-in git clone/pull/push/commit functionality of its own — this command family only ever managed a registry of local directories, and that registry is now `hyve env`. See [Environments](/docs/concepts/repositories) and the [`env` CLI reference](/docs/cli/env).
</Warning>

## What changed

`hyve git add/list/use/remove/status/path/branch/pull/push/sync/credentials` are all gone. None of them ever ran real git operations beyond a thin credentials-store wrapper — the actual clone/pull/push was always your own `git` CLI, called by hand or from CI. What they *did* do — register a local directory as the one `hyve reconcile`/`hyve cluster`/etc. operate against — is now `hyve env create [--path]`/`hyve env use`/`hyve env list`/`hyve env remove`.

## What still works

If you want your state directory backed by git, that's exactly the same as before: `git clone`, `git add`, `git commit`, `git push` — your own tooling, your own remote, your own credentials. Hyve reads and writes plain files in whatever directory `hyve env` has registered as active; it has no opinion about whether that directory happens to be a git working tree. See [Version Control](/docs/concepts/gitops) for the full picture.
