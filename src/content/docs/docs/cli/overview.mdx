The Hyve CLI manages the full lifecycle of Kubernetes clusters — in local mode, against a directory of YAML files (git-backed or not), or in cluster mode, as a client of a deployed cluster-mode API. Both modes share every command below; which one a given command talks to depends on the active [context](/docs/concepts/contexts): one pointing at a hyve-api server (and logged in) uses cluster mode, one pointing at a directory uses local mode.

## Command Structure

```bash
hyve <command> <subcommand> [arguments] [flags]

hyve --help
hyve cluster --help
hyve cluster create --help
```

## Global Flags

| Flag | Description |
|------|-------------|
| `--home <dir>` | Override the Hyve data directory (default: `~/.hyve`). Also configurable via the `HYVE_HOME` environment variable. |
| `--env <name>` | hyve-api environment to target for this one command, overriding `hyve environment use` (cluster mode only). |

```bash
hyve --home /tmp/hyve-test reconcile
# or
export HYVE_HOME=/tmp/hyve-test
hyve reconcile
```

## Commands

### reconcile

```bash
hyve reconcile                  # active context's directory
hyve reconcile --path .         # explicit path — typical in CI
hyve reconcile --dry-run
```

A no-op with an explanatory message in cluster mode — the controller reconciles continuously on its own. Mode and strict-delete are controlled by `hyve.yaml`; see [Configuration](/docs/configuration) and the [CI/CD guide](/docs/guides/cicd).

### context

Where the CLI's state lives — a local directory, a hyve-api server, or both — plus login and secrets.

```bash
hyve context create <name> [--path <dir>] [--api-url <url>]
hyve context list | current | use <name> | remove <name> | path [name]
hyve context login [--api-url <url>] [--org <name>]
hyve context logout | whoami
hyve context secrets list | get | set | unset
```

[Full reference →](/docs/cli/context)

### environment

Your organization's server-side environments (cluster mode only).

```bash
hyve environment list | create <name> | delete <name>
hyve environment use <name> | unset | current
hyve cluster list --env staging      # one-off override on any command
```

[Full reference →](/docs/cli/environment)

### apply

```bash
hyve apply -f <file>
```

Creates a single resource from a CR-shaped YAML file, auto-detecting its kind (`ClusterDefinition`/`Template`/`Workflow`). Cluster mode only.

### migrate

```bash
hyve migrate [path] [--write]                       # bulk-import into the logged-in cluster
hyve migrate to-cluster --to <kubeconfig> [--write]  # bootstrap a fresh cluster, no login needed
hyve migrate cluster --from <kc> --to <kc> --write --i-have-stopped-the-source-controller
```

Three different commands for three different jobs — see the [full reference](/docs/cli/migrate) for which one to use when.

### cluster

```bash
hyve cluster list
hyve cluster show <name>
hyve cluster create <name> --template <template> [--region <region>] [--set KEY=VALUE]
hyve cluster delete <name>
hyve cluster auth <name>
hyve cluster auth sync
hyve cluster deauth <name>
hyve cluster adopt <name> --template <template>
hyve cluster resources <name>
```

[Full reference →](/docs/cli/cluster)

### module

```bash
hyve module install
hyve module add <source>[@<version>]
hyve module update <source>
hyve module list
hyve module info <source>
hyve module validate
hyve module remove <source>
hyve module init <name>
```

[Full reference →](/docs/cli/module)

### template

```bash
hyve template create <name> --driver <source> --driver-version <ver> --region <region> [--set KEY=VALUE]
hyve template list
hyve template show <name>
hyve template delete <name>
hyve template validate <name>
```

[Full reference →](/docs/cli/template)

### workflow

```bash
hyve workflow run <name> --cluster <cluster> [--set KEY=VALUE]
hyve workflow list
hyve workflow show <name>
hyve workflow create <name> [--file <yaml>]
hyve workflow validate <name>
hyve workflow delete <name>
hyve workflow install
hyve workflow update <source>
```

[Full reference →](/docs/cli/workflow)

### resource

```bash
hyve resource list
hyve resource show <name>
hyve resource create <name> [--file <yaml>]
hyve resource delete <name>
hyve resource install
```

[Full reference →](/docs/cli/resource)

### organization

Superadmin management of organizations — the multi-tenant unit on a hyve-api install (cluster mode only).

```bash
hyve organization create <name> | list | delete <name>
hyve organization migrate <name> (--reconciling-cluster <pool-name> | --home)
```

[Full reference →](/docs/cli/organization)

### reconciling-cluster

The clusters an organization's resources reconcile on — store several, switch by name (cluster mode only).

```bash
hyve reconciling-cluster add <name> --kubeconfig-file <path>
hyve reconciling-cluster list | current
hyve reconciling-cluster use <name> | use --home
hyve reconciling-cluster remove <name>
hyve reconciling-cluster pool add | list          # superadmin
```

[Full reference →](/docs/cli/reconciling-cluster)

### cluster-config

Server-side only — runs inside the deployed controller/API pods, not an everyday end-user command:

```bash
hyve cluster-config controller run --namespace hyve-system
hyve cluster-config api run --namespace hyve-system
hyve cluster-config api create-user <username> --role admin
```

[Full reference →](/docs/cli/cluster-config)

## Environment Variables

| Variable | Purpose |
|----------|---------|
| `CIVO_TOKEN` | Civo API token (read by the Civo module) |
| `AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY` | AWS credentials (read by the EKS module via the AWS SDK chain) |
| `GOOGLE_APPLICATION_CREDENTIALS` | Path to GCP service account JSON (read by the GKE module via ADC) |
| `AZURE_TENANT_ID` / `AZURE_CLIENT_ID` / `AZURE_CLIENT_SECRET` | Azure service principal (read by the AKS module) |
| `HYVE_HOME` | Hyve data directory (default: `~/.hyve`). Equivalent to `--home` flag. |
| `HYVE_PARAM_<KEY>` | Injected into module operations from `spec.params` |

See the [CI/CD guide](/docs/guides/cicd) for configuring credentials in pipelines.

## Common Workflows

### Initial setup (local mode)

```bash
# 1. Authenticate with your cloud provider's own CLI (example: Civo)
civo apikey save my-token YOUR_CIVO_TOKEN && civo apikey use my-token

# 2. Point hyve at a directory (git-backed or not — see Contexts)
hyve context create production --path ~/repos/hyve-production

# 3. Install a module
hyve module add github.com/hyve-modules/civo@v1.0.0

# 4. Create a template
hyve template create my-template \
  --driver github.com/hyve-modules/civo \
  --driver-version v1.0.0 \
  --region PHX1 \
  --set node_size=g4s.kube.medium

# 5. Create a cluster from the template
hyve cluster create my-cluster --template my-template

# 6. Authenticate and connect
hyve cluster auth my-cluster
kubectl get nodes
```

### CI/CD pipeline

```yaml
# hyve.yaml at the repository root
reconcile:
  mode: cicd
  strictResourceDelete: true
```

```bash
git pull && hyve reconcile --path . && git add -A clusters cluster-state && git commit -m "hyve: reconcile" && git push
```

### Delete a cluster

```bash
# Sets spec.delete: true, then reconcile runs onDelete/afterDelete hooks and removes it
hyve cluster delete my-cluster
```

## Troubleshooting

<AccordionGroup>
  <Accordion title="hyve: command not found">
    ```bash
    sudo mv hyve /usr/local/bin/
    # or
    export PATH=$PATH:/path/to/hyve
    ```
  </Accordion>

  <Accordion title="No context configured">
    ```bash
    hyve context create production --path ~/repos/hyve-production
    hyve context use production
    ```
  </Accordion>

  <Accordion title="API authentication failed (cloud provider)">
    ```bash
    # Civo — authenticate with the Civo CLI (writes ~/.civo.json)
    civo apikey save my-token YOUR_CIVO_TOKEN
    civo apikey use my-token
    # or: export CIVO_TOKEN=your_token
    # AWS
    aws configure
    # GCP
    gcloud auth application-default login
    # Azure
    az login
    ```
  </Accordion>

  <Accordion title="Cluster-mode login failed">
    ```bash
    hyve context login --api-url https://hyve-api.example.com
    hyve context whoami   # confirm who you're authenticated as, and where
    ```
    See [Login](/docs/cli/context).
  </Accordion>

  <Accordion title="Module not found">
    ```bash
    hyve module install
    # or
    hyve module add github.com/hyve-modules/civo@v1.0.0
    ```
  </Accordion>
</AccordionGroup>
