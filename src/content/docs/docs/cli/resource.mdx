What hyve puts on a cluster is its template's resources plus that cluster's
own extras. A shared Resource is a Fleet HelmOp, Bundle or GitRepo spec
defined once, which templates and extras refer to by name ('--ref').
It has no targets of its own.

```text
  hyve template resource add   every cluster made from a template
  hyve cluster resource add    one cluster
  hyve resource create         a shared definition to refer to
```

```text
  hyve resource [command]
```

Aliases: `resource, resources, res`

**Flags**

```text
  -e, --env string                  environment (namespace) of the clusters (default: the context's; see 'hyve env use')
  -h, --help                        help for resource
      --kubeconfig string           talk to a management cluster with this kubeconfig instead of a signed-in server (admins, CI)
      --server string               saved server to use (default: the current one; see 'hyve context list')
      --template-namespace string   namespace of templates and shared resources (default: the context's, or capi-clusters)
```

### hyve resource apply

Applies hyve objects from YAML files. Objects without a namespace go in the
template namespace (a ClusterResource in the environment). A bundle entry
may give 'path: DIR' instead of resources; the manifests there, relative to
the file, are sent inline.

```text
  hyve resource apply -f FILE [flags]
```

**Flags**

```text
  -f, --filename stringArray   YAML file (repeatable)
  -h, --help                   help for apply
```

### hyve resource create

Create or replace a shared Resource in the template namespace

```text
  hyve resource create (--helm CHART | --git REPO | --path DIR) --name NAME [flags]
```

**Examples**

```text
  hyve resource create --name external-dns --helm external-dns --repo https://kubernetes-sigs.github.io/external-dns/ \
      --version 1.19.0 -N external-dns -f external-dns-values.yaml --secret cloudflare-dns
```

**Flags**

```text
      --branch string             git branch
      --correct-drift             have Fleet undo changes made to its objects on the cluster
      --dry-run                   print the Resource instead of creating it
      --git string                git repository URL
      --git-path stringArray      path in the repo (repeatable; default: the whole repo)
      --helm string               Helm chart (a name with --repo, or an oci:// URL)
  -h, --help                      help for create
      --name string               resource name (default: the chart, repo or ref name)
      --path string               local manifests: a file or directory of .yaml/.yml/.json, sent inline
      --release-name string       Helm release name (default: the resource name)
      --repo string               Helm repository URL
      --revision string           git revision (commit or tag)
      --secret stringArray        Secret (in the owner's namespace) for Fleet to copy to each cluster (repeatable)
      --set stringArray           Helm value key=value; dotted keys nest, JSON values are parsed (repeatable)
  -N, --target-namespace string   namespace for its objects on the cluster
  -f, --values string             Helm values file
      --version string            chart version (pin it in templates)
```

### hyve resource delete

Delete a shared Resource (templates and clusters referring to it report it missing)

```text
  hyve resource delete NAME [flags]
```

**Flags**

```text
  -h, --help   help for delete
```

### hyve resource list

List shared Resources, and every template and cluster resource hyve has delivered

```text
  hyve resource list [flags]
```

Aliases: `list, ls`

**Flags**

```text
  -A, --all-namespaces   delivered resources in every namespace
  -h, --help             help for list
```

### hyve resource show

Shows a shared Resource and the templates and clusters that refer to it.
A resource that isn't shared (one written into a template, or an extra on
a cluster) is shown as written there, with the Fleet object hyve delivers
it as; --template or --cluster picks one when several have that name.

```text
  hyve resource show NAME [flags]
```

**Examples**

```text
  hyve resource show podinfo
  hyve resource show flannel --template capd-small
  hyve resource show monitoring --cluster demo -o yaml
```

**Flags**

```text
      --cluster string    the extra on this cluster (in the environment)
  -h, --help              help for show
  -o, --output string     "yaml" or "json" for the object itself
      --template string   the resource written into this template
```

### hyve resource status

What's on a cluster and why, or each resource's state on each of a template's clusters

```text
  hyve resource status (CLUSTER | --template TEMPLATE) [flags]
```

**Flags**

```text
  -h, --help              help for status
      --template string   a matrix of this template's clusters and resources
```
