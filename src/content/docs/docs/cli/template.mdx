### hyve template apply

Applies hyve objects from YAML files. Objects without a namespace go in the
template namespace (a ClusterResource in the environment). A bundle entry
may give 'path: DIR' instead of resources; the manifests there, relative to
the file, are sent inline.

```text
  hyve template apply -f FILE [flags]
```

**Flags**

```text
  -f, --filename stringArray   YAML file (repeatable)
  -h, --help                   help for apply
```

### hyve template create

Creates a ClusterTemplate in the template namespace, beside its ClusterClass.
--from-clusterclass also copies every variable the ClusterClass declares,
with its default (or null), as a starting point to edit. Add resources with
'hyve template resource add'; for anything more, write the YAML and use
'hyve template apply -f'.

```text
  hyve template create NAME (--class CLASS | --from-clusterclass CLASS) [flags]
```

**Examples**

```text
  hyve template create capd-small --class capd --workers 1 --schedule "0 20 * * *"
  hyve template create gke-small --from-clusterclass gke --set project=my-proj --lock project
```

**Flags**

```text
      --class string               ClusterClass to build from
      --class-namespace string     the ClusterClass's namespace (default: the template's)
      --control-plane int          control-plane replicas (default: 1 for a machine-based control plane, none for a managed one)
      --description string         description
      --dry-run                    print the template instead of creating it
      --from-clusterclass string   ClusterClass to build from, copying its variables and defaults
  -h, --help                       help for create
      --label stringArray          label key=value on every cluster (repeatable)
      --lock strings               variables clusters can't change (repeatable)
      --schedule string            cron schedule; each cluster expires at its next occurrence (e.g. "0 20 * * 5")
      --set stringArray            variable name=value (repeatable; JSON values are parsed)
      --version string             Kubernetes version (default: the class's hyve.io/default-version)
      --worker-class string        worker class (default: the ClusterClass's first)
      --worker-type string         machineDeployment or machinePool (default: whichever the ClusterClass defines)
      --workers int                worker replicas (default 1)
```

### hyve template delete

Deletes a ClusterTemplate. The Fleet objects made from its resources go with
it, so Fleet removes those resources from its clusters. The clusters
themselves stay, and keep their variables.

```text
  hyve template delete NAME [flags]
```

**Flags**

```text
  -h, --help   help for delete
```

#### hyve template resource add

Add a resource to a template, or replace the one of the same name

```text
  hyve template resource add TEMPLATE (--helm CHART | --git REPO | --path DIR | --ref RESOURCE) [flags]
```

**Examples**

```text
  hyve template resource add civo --helm traefik --repo https://traefik.github.io/charts --version 37.1.0 -N traefik --set service.type=LoadBalancer
  hyve template resource add civo --ref external-dns --secret cloudflare-dns
```

**Flags**

```text
      --branch string             git branch
      --correct-drift             have Fleet undo changes made to its objects on the cluster
      --git string                git repository URL
      --git-path stringArray      path in the repo (repeatable; default: the whole repo)
      --helm string               Helm chart (a name with --repo, or an oci:// URL)
  -h, --help                      help for add
      --name string               resource name (default: the chart, repo or ref name)
      --path string               local manifests: a file or directory of .yaml/.yml/.json, sent inline
      --ref string                a shared Resource (see 'hyve resource create'); --set and -f then override its Helm values
      --release-name string       Helm release name (default: the resource name)
      --repo string               Helm repository URL
      --revision string           git revision (commit or tag)
      --secret stringArray        Secret (in the owner's namespace) for Fleet to copy to each cluster (repeatable)
      --set stringArray           Helm value key=value; dotted keys nest, JSON values are parsed (repeatable)
  -N, --target-namespace string   namespace for its objects on the cluster
  -f, --values string             Helm values file
      --version string            chart version (pin it in templates)
```
