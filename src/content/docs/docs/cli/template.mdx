### hyve template apply

Applies ClusterTemplates from YAML files, and ClusterClasses with their
provider templates (CivoClusterTemplate, DockerMachineTemplate...), classes
first. Objects without a namespace go in the template namespace. For
Deployments and ClusterGroups use 'hyve deploy apply', or 'hyve apply' for
everything at once.

A template's resources (before Deployments) are still accepted:
hyve-controller turns each into a Deployment aimed at the template.

```text
  hyve template apply -f FILE|DIR|- [flags]
```

**Flags**

```text
  -f, --filename stringArray   YAML file, directory, or - for standard input (repeatable)
  -h, --help                   help for apply
```

### hyve template convert

Reads old hyve Templates (built with hyve-capi-module, hyve-civo-module or
hyve-unraid-k3s-module) and herd ClusterTemplates (herd.io), from YAML files
or from a cluster, and converts them into hyve ClusterTemplates: flavor
presets expanded, params mapped onto the ClusterClass, lockParams onto
locked variables, the schedule, and Helm and git resources as Fleet specs
(which hyve-controller turns into Deployments aimed at the template).
Prints them as YAML, or creates them in the template namespace with
--apply. What hyve can't express (workflows, other modules, locks on
non-variables) is listed on stderr.

--relabel-clusters (with --apply) also labels the clusters herd made from
each herd template with the new hyve.io/template labels, so they get the
template's Deployments and locks.

```text
  hyve template convert (-f FILE|DIR ... | --from-cluster) [flags]
```

Aliases: `convert, import`

**Examples**

```text
  hyve template convert -f ./templates                                # print
  hyve template convert --from-cluster --source-kubeconfig old.yaml --kubeconfig new.yaml --apply --relabel-clusters
```

**Flags**

```text
      --apply                       create the ClusterTemplates instead of printing them
  -f, --filename stringArray        file or directory of old hyve Templates or herd ClusterTemplates (repeatable)
      --from-cluster                read them from a cluster (see --source-kubeconfig)
  -h, --help                        help for convert
      --kubeconfig string           talk to a management cluster with this kubeconfig instead of a signed-in server (admins, CI)
      --prefix-namespace            name every ClusterTemplate <old namespace>-<name>
      --relabel-clusters            with --apply, label clusters made from herd templates with the hyve.io/template labels
      --server string               saved server to use (default: the current one; see 'hyve context list')
      --source-context string       kubeconfig context for --from-cluster
      --source-kubeconfig string    kubeconfig for --from-cluster
      --source-namespace string     only this namespace's templates (default: all)
      --template-namespace string   namespace of templates and their Deployments (default: the context's, or capi-clusters)
```

### hyve template create

Creates a ClusterTemplate in the template namespace, beside its ClusterClass.
--from-clusterclass also copies every variable the ClusterClass declares,
with its default (or null), as a starting point to edit. For anything
more, write the YAML and use 'hyve template apply -f'. What its clusters
run is deployed to it: 'hyve deploy create NAME ... --to template/NAME'.

```text
  hyve template create NAME (--class CLASS | --from-clusterclass CLASS) [flags]
```

**Examples**

```text
  hyve template create capd-small --class capd --workers 1 --schedule "0 20 * * *"
  hyve template create gke-small --from-clusterclass gke --set project=my-proj --lock project
```

**Flags**

```text
      --class string               ClusterClass to build from
      --class-namespace string     the ClusterClass's namespace (default: the template's)
      --control-plane int          control-plane replicas (default: 1 for a machine-based control plane, none for a managed one)
      --description string         description
      --dry-run                    print the template instead of creating it
      --from-clusterclass string   ClusterClass to build from, copying its variables and defaults
  -h, --help                       help for create
      --label stringArray          label key=value on every cluster (repeatable)
      --lock strings               variables clusters can't change (repeatable)
      --schedule string            cron schedule; each cluster expires at its next occurrence (e.g. "0 20 * * 5")
      --set stringArray            variable name=value (repeatable; JSON values are parsed)
      --version string             Kubernetes version (default: the class's hyve.io/default-version)
      --worker-class string        worker class (default: the ClusterClass's first)
      --worker-type string         machineDeployment or machinePool (default: whichever the ClusterClass defines)
      --workers int                worker replicas (default 1)
```

### hyve template delete

Deletes a ClusterTemplate, and the Fleet group hyve keeps for it, so
Deployments aimed only at the template reach none of its clusters any more
and Fleet removes them there. The Deployments themselves, and the clusters,
stay; the clusters keep their variables.

```text
  hyve template delete NAME [flags]
```

**Flags**

```text
  -h, --help   help for delete
```

### hyve template render

Reads ClusterTemplates and ClusterClasses from YAML files and prints the
Cluster hyve would create from the template, filled in. A template file
that still lists resources (from before Deployments) also gets the
Deployments hyve-controller turns them into, aimed at the template's group;
shared Resources they refer to can be given too. Nothing is contacted.
Without the ClusterClass among the files, its defaults (version, workers)
can't be filled in.

```text
  hyve template render -f FILE... [--template NAME] [--name CLUSTER] [flags]
```

**Examples**

```text
  hyve template render -f fleet/capi/templates/civo.yaml -f fleet/capi/classes/civo.yaml --name demo -e ci
```

**Flags**

```text
  -e, --env string             the cluster's environment (default "default")
  -f, --filename stringArray   YAML file with ClusterTemplates, ClusterClasses or (older) shared Resources (repeatable)
  -h, --help                   help for render
      --name string            the cluster's name (default "example")
      --set stringArray        ClusterClass variable name=value (repeatable)
      --template string        which template, when the files hold several
```
