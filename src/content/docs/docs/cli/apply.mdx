Creates or updates, from YAML, whatever hyve knows: ClusterTemplates,
ClusterClasses with their provider templates (CivoClusterTemplate,
DockerMachineTemplate...), Deployments (Fleet GitRepos, HelmOps and
Bundles) and ClusterGroups. It's the same whether they exist or not, so a
pipeline or a repository of them can run it every time. ClusterClasses go
before the templates built on them, and groups before the Deployments
that target them. Objects without a namespace go in the template
namespace. '-f -' reads standard input; a directory's .yaml, .yml and
.json files are read, below it too.

'hyve template apply' takes only templates and classes, and 'hyve deploy
apply' only Deployments and groups.

```text
  hyve apply -f FILE|DIR|- [flags]
```

**Examples**

```text
  hyve apply -f platform/
  sed "s/VERSION/$VERSION/" web.yaml | hyve apply -f - --wait
```

**Flags**

```text
  -f, --filename stringArray        YAML file, directory, or - for standard input (repeatable)
  -h, --help                        help for apply
      --kubeconfig string           talk to a management cluster with this kubeconfig instead of a signed-in server (admins, CI)
      --server string               saved server to use (default: the current one; see 'hyve context list')
      --template-namespace string   namespace of templates and their Deployments (default: the context's, or capi-clusters)
      --timeout duration            how long --wait waits (default 10m0s)
      --wait                        wait until every cluster it targets runs the change, and fail if one can't (for CI)
```
