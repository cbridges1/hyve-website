Create, change, list and delete the Secrets resources copy to clusters

```text
  hyve secrets [command]
```

Aliases: `secrets, secret`

**Flags**

```text
  -e, --env string                  environment (namespace) of the clusters (default: the context's; see 'hyve env use')
  -h, --help                        help for secrets
      --kubeconfig string           talk to a management cluster with this kubeconfig instead of a signed-in server (admins, CI)
      --server string               saved server to use (default: the current one; see 'hyve context list')
      --template-namespace string   namespace of templates and shared resources (default: the context's, or capi-clusters)
```

### hyve secrets create

Creates a Secret in the template namespace (or --namespace), for template
resources and cluster extras to name in their secrets. Values come from
--from-literal, environment variables (--from-env) or files (--from-file);
they're never printed.

```text
  hyve secrets create NAME (--from-literal key=value | --from-env KEY | --from-file key=path)... [flags]
```

**Examples**

```text
  CF_TOKEN=... hyve secrets create cloudflare-dns --from-env api-token=CF_TOKEN
  CIVO_TOKEN=... hyve secrets create civo-credentials -n default --from-env token=CIVO_TOKEN
  hyve secrets create registry --type kubernetes.io/dockerconfigjson --from-file .dockerconfigjson=$HOME/.docker/config.json
```

**Flags**

```text
      --from-env stringArray       KEY, or key=VARIABLE: the value of an environment variable (repeatable)
      --from-file stringArray      key=path, or a path (the key is the file's name): the file's contents (repeatable)
      --from-literal stringArray   key=value (repeatable; it lands in shell history, so prefer --from-env or --from-file for real secrets)
  -h, --help                       help for create
  -l, --label stringArray          label key=value (repeatable)
  -n, --namespace string           the Secret's namespace (default: the template namespace)
      --type string                the Secret's type (default "Opaque")
```

### hyve secrets list

Lists, by name only, the Secrets that template resources (in the template
namespace) and cluster extras (in the environment) have Fleet copy to their
clusters, and whether each exists, with their keys; it never reads values
('hyve secrets show NAME --reveal' does).
Create missing ones with 'hyve secrets create', or however your install
manages secrets: an operator such as Infisical's or External Secrets,
sealed-secrets.

```text
  hyve secrets list [flags]
```

Aliases: `list, ls`

**Flags**

```text
  -h, --help   help for list
```

### hyve secrets set

Changes a Secret's keys: the values given are added or replace the keys of
the same name, --remove deletes keys, and the rest stay as they are.
Clusters get the change the next time Fleet copies the Secret.

```text
  hyve secrets set NAME [--from-literal key=value | --from-env KEY | --from-file key=path]... [--remove KEY]... [flags]
```

**Examples**

```text
  CF_TOKEN=... hyve secrets set cloudflare-dns --from-env api-token=CF_TOKEN
  hyve secrets set registry --remove old-key
```

**Flags**

```text
      --from-env stringArray       KEY, or key=VARIABLE: the value of an environment variable (repeatable)
      --from-file stringArray      key=path, or a path (the key is the file's name): the file's contents (repeatable)
      --from-literal stringArray   key=value (repeatable; it lands in shell history, so prefer --from-env or --from-file for real secrets)
  -h, --help                       help for set
  -n, --namespace string           the Secret's namespace (default: the template namespace)
      --remove stringArray         a key to delete (repeatable)
```

### hyve secrets show

Shows a Secret in the template namespace (or --namespace): its type,
labels and keys. Values stay hidden unless you pass --reveal. It's read as
you, so it needs RBAC to get Secrets there.

```text
  hyve secrets show NAME [flags]
```

**Flags**

```text
  -h, --help               help for show
  -n, --namespace string   the Secret's namespace (default: the template namespace)
  -o, --output string      "yaml" or "json" for the object itself
      --reveal             print the values
```
