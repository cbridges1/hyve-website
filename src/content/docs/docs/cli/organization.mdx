`hyve organization` manages [organizations](/docs/concepts/multi-tenancy) — hyve-api's own multi-tenant isolation unit, one Kubernetes namespace plus a set of environments/RBAC bindings/reconciling-cluster assignment, backed by a real row in hyve-api's own datastore rather than a Kubernetes object. Cluster-mode only — organizations have no local-directory equivalent — every command here requires an active session (`hyve context login`) against a superadmin account.

<Note>
  Creating an organization only provisions the namespace/environment — it grants no one access. Use `hyve cluster-config api create-user` (see [Access Control](/docs/concepts/access-control)) to create its first account.
</Note>

## hyve organization create

```bash
hyve organization create <name> [--admin-identity <identity> --admin-role <role>] [--reconciling-cluster <name>]
```

<ParamField path="<name>" type="string" required>
  The new organization's name — also becomes its Kubernetes namespace, and must not collide with `hyve-system` or any form of `control plane`, both permanently reserved.
</ParamField>

<ParamField path="--admin-identity" type="string">
  Identity (username or OIDC subject) to grant an initial admin binding to, in the same transaction as the organization itself. Requires `--admin-role`.
</ParamField>

<ParamField path="--admin-role" type="string">
  Role for `--admin-identity` (`admin` or `read-only`).
</ParamField>

<ParamField path="--reconciling-cluster" type="string">
  Name of a pool [reconciling cluster](/docs/concepts/multi-tenancy#reconciling-clusters-where-a-tenants-resources-actually-live) (see `hyve reconciling-cluster pool add`) this organization's resources should live on instead of the control plane's own home cluster. Omit to use the home cluster; the organization's own admin can later add and switch to clusters of its own.
</ParamField>

```bash
hyve organization create acme --reconciling-cluster cell-a
```

## hyve organization list

```bash
hyve organization list
```

Lists every organization on the install, its namespace, plan, current reconciling cluster (if any), and whether it's mid-migration.

---

## hyve organization delete

```bash
hyve organization delete <name>
```

Marks the organization for deletion and issues a standard Kubernetes namespace delete — permanent, and asynchronous: Kubernetes' own cascade tears everything down, and the organization's row disappears once the namespace finishes terminating.

<Warning>
  The control plane's own organization (`hyve-system`) can never be deleted this way, no matter who's asking.
</Warning>

## hyve organization migrate

```bash
hyve organization migrate <name> (--reconciling-cluster <name> | --home)
```

Moves an organization onto a different [reconciling cluster](/docs/concepts/multi-tenancy#reconciling-clusters-where-a-tenants-resources-actually-live), or back to the control plane's own home cluster.

<ParamField path="--reconciling-cluster" type="string">
  Name of a pool reconciling cluster (see `hyve reconciling-cluster pool add`/`pool list`) to move the organization onto. To switch between an organization's *own* stored clusters, its admin uses [`hyve reconciling-cluster use`](/docs/cli/reconciling-cluster) instead.
</ParamField>

<ParamField path="--home" type="boolean">
  Move the organization back to the control plane's own home cluster. Only possible for an install that has one — see `--home-cluster` on `hyve cluster-config api run`.
</ParamField>

```bash
hyve organization migrate acme --reconciling-cluster cell-b
```

<Info>
  Renaming an organization's own display name (its namespace never changes) goes through the same underlying `PATCH /organizations/{name}` this command uses — reach it via the web console's Organizations page today; a dedicated `hyve organization rename` CLI command may follow.
</Info>

## Environments

An organization's environments are managed with [`hyve environment`](/docs/cli/environment) (`list`/`create`/`delete`/`use`, with `--org <name>` for a superadmin acting on another organization). The older `hyve organization environments` and `hyve organization create-environment` still work but are deprecated.
