Local mode runs a standalone hyve on a K3s cluster in Docker that the CLI
manages: the same templates and commands as a server, with nothing to run.
'hyve local up' creates it and signs you in as its admin, as the "local"
context. CAPD clusters run as containers next to it.

```text
  hyve local [command]
```

**Flags**

```text
  -h, --help   help for local
```

### hyve local down

Deletes the local cluster and its context. Its state (Cluster API objects,
templates, Deployments) is saved first and restored by the next 'hyve local
up', whose clusters' agents reconnect by themselves. CAPD clusters are
containers of their own and keep running; delete them first ('hyve
cluster delete') if you're done with them.

```text
  hyve local down [flags]
```

**Flags**

```text
      --discard-state   remove the saved state too, forgetting the clusters
  -h, --help            help for down
```

### hyve local restore

Restore saved state into the local cluster ('hyve local up' does this for a new one)

```text
  hyve local restore [flags]
```

**Flags**

```text
      --dir string   where to restore from (default: the state directory)
  -h, --help         help for restore
```

### hyve local save

Save the local cluster's state now (hyve also saves after each change)

```text
  hyve local save [flags]
```

**Flags**

```text
      --dir string   where to save (default: the state directory)
  -h, --help         help for save
```

### hyve local status

Show whether the local cluster exists and is running

```text

```

**Flags**

```text
  -h, --help   help for status
```

### hyve local stop

Stop the local cluster until the next 'hyve local up' or local-mode command (child clusters keep running; their agents reconnect when it starts)

```text
  hyve local stop [flags]
```

**Flags**

```text
  -h, --help   help for stop
```

### hyve local ui

Open local mode's web UI, signed in (the same as 'hyve ui --server local')

```text
  hyve local ui [flags]
```

**Flags**

```text
  -h, --help         help for ui
      --no-browser   print the URL instead of opening a browser
      --port int     local port for serving a host the browser doesn't trust (0 picks one) (default 30445)
```

### hyve local up

Create or start the local cluster, install hyve in it and sign in

```text
  hyve local up [flags]
```

**Examples**

```text
  hyve local up
  hyve local up --public-url https://hyve.example.com   # children outside Docker reach it through your tunnel
```

**Flags**

```text
      --apiserver-arg stringArray   extra kube-apiserver flag for K3s (repeatable)
      --full                        install the CAPI Operator and cert-manager, as a server install does, instead of the lean install
      --gogc string                 GOGC for K3s and every controller, trading a little CPU for memory (default "40")
  -h, --help                        help for up
      --image string                hyve image (default: the release's, or 'hyve:dev' for a build from source; a local Docker image is imported)
      --k3s-image string            K3s image (default "rancher/k3s:v1.34.12-k3s1")
      --port int                    host port the host endpoint listens on (default 30444)
      --providers strings           Cluster API providers to add now (default: none; known ones, such as docker and kubeadm, are added when first needed)
      --public-url string           the host endpoint's URL for clusters outside Docker's kind network (a tunnel you run)
      --state-dir string            keep the saved state here (remembered) instead of ~/.hyve/local/state, such as in a directory CI caches
      --timeout duration            how long to wait (default 20m0s)
```
