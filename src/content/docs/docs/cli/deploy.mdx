A Deployment is one Fleet object: a GitRepo (--git), a HelmOp (--helm) or a
Bundle (--path, manifests sent inline). It's delivered to every cluster its
targets name, now and later:

```text
  template/NAME      every cluster made from a template
  class/NAME         every cluster of a ClusterClass (e.g. every Civo cluster)
  env/NAME           every cluster in an environment
  cluster/ENV/NAME   one cluster
  group/NAME         a Fleet ClusterGroup of your own
  all                every cluster hyve manages
  host               the management cluster
```

hyve keeps a Fleet ClusterGroup for each template and environment; CAAPF
keeps one for each ClusterClass. A Deployment lives in the template
namespace, or in an environment's namespace when that environment's
clusters are all it targets, or in fleet-local for the host. Deployments
written by hand (in git, with kubectl) are listed the same way.

```text
  hyve deploy [command]
```

Aliases: `deploy, deployment, deployments`

**Flags**

```text
  -h, --help                help for deploy
      --kubeconfig string   talk to a management cluster with this kubeconfig instead of a signed-in server (admins, CI)
      --server string       saved server to use (default: the current one; see 'hyve context list')
```

### hyve deploy apply

Creates or updates Deployments from YAML: Fleet GitRepos, HelmOps and
Bundles, and the ClusterGroups they target. It's the same whether they
exist or not, so a pipeline can run it every time. Objects without a
namespace go in the template namespace. '-f -' reads standard input.

The fields the file gives are set (server-side apply); fields it leaves out
that were set elsewhere (in the UI, with 'hyve deploy update') stay.

```text
  hyve deploy apply -f FILE [flags]
```

**Examples**

```text
  hyve deploy apply -f deployments/ --wait
  sed "s/VERSION/$VERSION/" web.yaml | hyve deploy apply -f - --wait --timeout 15m
```

**Flags**

```text
  -f, --filename stringArray   YAML file, directory of .yaml/.yml/.json files, or - for standard input (repeatable)
  -h, --help                   help for apply
      --timeout duration       how long --wait waits (default 10m0s)
      --wait                   wait until every cluster it targets runs the change, and fail if one can't (for CI)
```

### hyve deploy create

Deliver a Helm chart, git paths or manifests to clusters

```text
  hyve deploy create NAME (--helm CHART --repo URL | --git URL | --path DIR) --to TARGET... [flags]
```

**Examples**

```text
  hyve deploy create podinfo --helm podinfo --repo https://stefanprodan.github.io/podinfo --version 6.7.1 \
      -N podinfo --to template/civo-podinfo
  hyve deploy create wg --git https://github.com/org/config.git --git-path workloads/civo-wg --to template/civo-wg
  hyve deploy create monitoring --helm kube-prometheus-stack --repo https://prometheus-community.github.io/helm-charts \
      --to all --rollout canary
  hyve deploy create debug --path ./debug --to cluster/dev/web
  GIT_TOKEN=... hyve deploy create nexus-config --git https://github.com/org/nexus-config.git --git-path fleet \
      --username me --token-env GIT_TOKEN --to host
```

**Flags**

```text
      --branch string             git branch
      --correct-drift             have Fleet undo changes made to its objects on the cluster
      --dry-run                   print the Fleet object instead of saving it
      --git string                git repository URL
      --git-path stringArray      path in the repo (repeatable; default: the whole repo)
      --helm string               Helm chart (a name with --repo, or an oci:// URL)
  -h, --help                      help for create
  -n, --namespace string          where the Deployment lives (default: picked from its targets)
      --path string               local manifests: a file or directory of .yaml/.yml/.json, sent inline
      --paused                    create it paused: nothing changes on clusters until 'hyve deploy resume'
      --release-name string       Helm release name (default: the resource name)
      --repo string               Helm repository URL
      --revision string           git revision (commit or tag)
      --rollout string            all (at once), one-at-a-time, or canary (clusters labelled hyve.io/canary=true first); not for --git, whose fleet.yaml says
      --secret stringArray        Secret (in the owner's namespace) for Fleet to copy to each cluster (repeatable)
      --set stringArray           Helm value key=value; dotted keys nest, JSON values are parsed (repeatable)
  -N, --target-namespace string   namespace for its objects on the cluster
      --timeout duration          how long --wait waits (default 10m0s)
      --to stringArray            target: template/NAME, class/NAME, env/NAME, cluster/ENV/NAME, group/NAME, all or host (repeatable)
      --token-env string          environment variable holding the git token
      --token-file string         file holding the git token
      --username string           git username, for a private --git repo
  -f, --values string             Helm values file
      --version string            chart version (pin it in templates)
      --wait                      wait until every cluster it targets runs the change, and fail if one can't (for CI)
```

#### hyve deploy secret create

Creates a Secret in the template namespace (or --namespace), for the
Deployments there to copy to clusters (their downstreamResources). Values come from
--from-literal, environment variables (--from-env) or files (--from-file);
they're never printed.

```text
  hyve deploy secret create NAME (--from-literal key=value | --from-env KEY | --from-file key=path)... [flags]
```

**Examples**

```text
  CF_TOKEN=... hyve deploy secret create cloudflare-dns --from-env api-token=CF_TOKEN
  CIVO_TOKEN=... hyve deploy secret create civo-credentials -n default --from-env token=CIVO_TOKEN
  hyve deploy secret create registry --type kubernetes.io/dockerconfigjson --from-file .dockerconfigjson=$HOME/.docker/config.json
```

**Flags**

```text
      --from-env stringArray       KEY, or key=VARIABLE: the value of an environment variable (repeatable)
      --from-file stringArray      key=path, or a path (the key is the file's name): the file's contents (repeatable)
      --from-literal stringArray   key=value (repeatable; it lands in shell history, so prefer --from-env or --from-file for real secrets)
  -h, --help                       help for create
  -l, --label stringArray          label key=value (repeatable)
  -n, --namespace string           the Secret's namespace (default: the template namespace)
      --type string                the Secret's type (default "Opaque")
```

#### hyve deploy secret set

Changes a Secret's keys: the values given are added or replace the keys of
the same name, --remove deletes keys, and the rest stay as they are.
Clusters get the change the next time Fleet copies the Secret.

```text
  hyve deploy secret set NAME [--from-literal key=value | --from-env KEY | --from-file key=path]... [--remove KEY]... [flags]
```

**Examples**

```text
  CF_TOKEN=... hyve deploy secret set cloudflare-dns --from-env api-token=CF_TOKEN
  hyve deploy secret set registry --remove old-key
```

**Flags**

```text
      --from-env stringArray       KEY, or key=VARIABLE: the value of an environment variable (repeatable)
      --from-file stringArray      key=path, or a path (the key is the file's name): the file's contents (repeatable)
      --from-literal stringArray   key=value (repeatable; it lands in shell history, so prefer --from-env or --from-file for real secrets)
  -h, --help                       help for set
  -n, --namespace string           the Secret's namespace (default: the template namespace)
```

### hyve deploy update

Changes a Deployment; only what's given changes.

--helm, --git or --path replace the whole source (give it all: --helm with
--repo, --version and values). Without them, the other source flags change
just their own field and the rest stays, which is how a release goes out:
```text
  --version, --repo, --release-name   a Helm chart's
  --set, -f                           merged over its Helm values
  --branch, --revision, --git-path    a git source's (--branch clears a pinned revision)
  -N, --secret, --correct-drift       any source's
```

Targets and the rollout are changed only when given. What hyve doesn't
model (targetCustomizations, diff, ...) is kept. --wait waits until every
cluster runs the change and fails if one can't, for CI.

```text
  hyve deploy update NAME [source flags] [--to ... | --add-to ... | --remove-to ...] [--rollout ...] [flags]
```

**Examples**

```text
  hyve deploy update podinfo --version 6.8.0 --wait
  hyve deploy update web --set image.tag="$GIT_SHA" --rollout canary --wait --timeout 20m
  hyve deploy update config --revision v1.4.3
  hyve deploy update podinfo --helm podinfo --repo https://stefanprodan.github.io/podinfo --version 6.8.0 --rollout one-at-a-time
  hyve deploy update podinfo --add-to class/civo
```

**Flags**

```text
      --add-to stringArray        add a target (repeatable)
      --branch string             git branch
      --correct-drift             have Fleet undo changes made to its objects on the cluster
      --dry-run                   print the Fleet object instead of saving it
      --git string                git repository URL
      --git-path stringArray      path in the repo (repeatable; default: the whole repo)
      --helm string               Helm chart (a name with --repo, or an oci:// URL)
  -h, --help                      help for update
  -n, --namespace string          where the Deployment lives (default: picked from its targets)
      --path string               local manifests: a file or directory of .yaml/.yml/.json, sent inline
      --paused                    create it paused: nothing changes on clusters until 'hyve deploy resume'
      --release-name string       Helm release name (default: the resource name)
      --remove-to stringArray     remove a target (repeatable)
      --repo string               Helm repository URL
      --revision string           git revision (commit or tag)
      --rollout string            all (at once), one-at-a-time, or canary (clusters labelled hyve.io/canary=true first); not for --git, whose fleet.yaml says
      --secret stringArray        Secret (in the owner's namespace) for Fleet to copy to each cluster (repeatable)
      --set stringArray           Helm value key=value; dotted keys nest, JSON values are parsed (repeatable)
  -N, --target-namespace string   namespace for its objects on the cluster
      --timeout duration          how long --wait waits (default 10m0s)
      --to stringArray            replace the targets (repeatable)
      --token-env string          environment variable holding the git token
      --token-file string         file holding the git token
      --username string           git username, for a private --git repo
  -f, --values string             Helm values file
      --version string            chart version (pin it in templates)
      --wait                      wait until every cluster it targets runs the change, and fail if one can't (for CI)
```

### hyve deploy wait

Waits until Fleet has taken in a Deployment's latest change (for a git
source, its latest commit) and every cluster it targets has applied it and
is ready. It fails (exits non-zero) when the timeout passes, or when the
Deployment or a cluster has an error that lasts 30 seconds; the clusters
that aren't done are listed. A paused Deployment fails at once.

create, update, apply, force and resume take --wait to do the same.

```text
  hyve deploy wait NAME [flags]
```

**Examples**

```text
  hyve deploy update web --version "$VERSION" && hyve deploy wait web --timeout 15m
```

**Flags**

```text
  -h, --help               help for wait
  -n, --namespace string   the Deployment's namespace
      --timeout duration   how long to wait (default 10m0s)
```
