The `hyve env` command group registers and switches between **environments** — named pointers to a local directory, a cluster-mode API URL, or both. See [Environments](/docs/concepts/repositories) for the full concept.

<Info>
  This replaces an earlier `hyve git`/`hyve set-state` split (both removed). Hyve never clones, pulls, pushes, or commits anything — `hyve env` only ever manages entries in a local registry (`~/.hyve/hyve.db`).
</Info>

## Commands

### hyve env create

Register a new environment and make it active immediately.

```bash
hyve env create [name] [--path <dir>] [--api-url <url>]
```

<ParamField path="name" type="string">
  Name for the environment. Defaults to `--path`'s directory basename (deduplicated with `-2`, `-3`, ... on collision) — required when registering `--api-url` alone, since there's no directory to derive a default from.
</ParamField>

<ParamField path="--path" type="string">
  Local directory to register. Defaults to the current working directory, unless `--api-url` is given alone, in which case no local directory is registered at all.
</ParamField>

<ParamField path="--api-url" type="string">
  A cluster API URL to pre-register for `hyve login` to target later. Stores no credential and does not authenticate anything by itself — see [`hyve login`](/docs/cli/login).
</ParamField>

**Registration only** — this never clones, pulls, commits, or pushes anything. If you want the directory kept in sync with a git remote, that's entirely your own `git` CLI: clone it yourself before registering it, then `git pull`/`git add`/`git commit`/`git push` around your workflow as usual.

**Examples:**

```bash
# A local directory
hyve env create production --path ~/repos/hyve-prod

# A cluster-mode target (no local directory)
hyve env create prod-cluster --api-url https://hyve-api.example.com

# Both — a directory AND a remembered cluster target
hyve env create staging --path ~/repos/hyve-staging --api-url https://hyve-api-staging.example.com
```

### hyve env list

List every registered environment, marking which is active.

```bash
hyve env list
```

### hyve env current

Show the currently-active environment.

```bash
hyve env current
```

### hyve env use

Switch the active environment.

```bash
hyve env use <name>
```

<Note>
  Switching environments never affects your `hyve login` session — they're independent. See [Environments — cluster mode](/docs/concepts/repositories#cluster-mode-an-api-url-no-local-directory-required).
</Note>

### hyve env remove

Deregister an environment. The directory itself (and everything in it) is left untouched on disk — hyve never owned it.

```bash
hyve env remove <name>
```

### hyve env path

Print an environment's local path.

```bash
hyve env path [name]   # defaults to the active environment
```
